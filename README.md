# 秒杀系统项目
## 项目介绍
基于SpringBoot + Redis + RabbitMQ + MyBatis-Plus实现的高并发秒杀系统。
## 项目简介
本秒杀系统使用一套后端服务，同时支撑微信小程序用户端与管理后台。
基于Spring Security的Filter过滤器链实现JWT身份认证与权限校验。
使用Redis预加载库存、削峰限流；RabbitMQ异步扣减库存，依靠本地消息表实现消息可靠投递，并通过幂等控制防止超卖。
项目统一异常处理，代码分层规范，集成Swagger接口文档。

## 核心功能
1. 用户注册登录，基于JWT完成身份认证，通过Filter过滤器链实现请求拦截与权限校验
2. 秒杀预订单机制，利用Redis+Lua脚本实现库存预扣减
3. RabbitMQ异步处理库存变更，实现消息可靠投递、幂等消费，保证消息不丢失、不重复消费
4. MySQL使用乐观锁控制并发更新，防止库存超卖，保障数据库数据一致性

## 项目亮点
1. **身份认证与权限控制**
   采用JWT生成令牌，自定义Filter过滤器拦截所有请求；解析Token后将用户信息存入ThreadLocal，供全链路获取。 
   权限校验使用SpringSecurity原生能力，基于角色做访问控制，区分普通用户与管理员接口。
   请求处理完成后清理ThreadLocal，避免线程复用带来的用户信息串号问题。

2. **Redis + Lua脚本防超卖**
   秒杀商品库存提前预热到Redis缓存，减少大量请求直接打MySQL。使用Lua脚本保证Redis预扣库存的原子性，防止并发场景下的超卖。
   采用预订单设计：先预扣Redis库存生成预订单，用户确认下单后才扣减数据库库存，无效超时订单自动释放缓存库存，实现流量削峰。

3. **RabbitMQ可靠消息 + 幂等消费**
   使用本地消息表+MQ生产者Confirm回调，保障消息投递不丢失；消费端通过消费记录表实现幂等，避免MQ重复投递造成多次扣减库存。
   异步执行数据库库存更新，把耗时的DB操作丢入MQ，实现请求快速返回，提升接口吞吐量。

4. **MySQL乐观锁保证数据库一致性**
   更新库存时使用版本号乐观锁，在数据库层面防止并发超卖；
   配合定时任务（Spring Scheduled）定时扫描超时未确认的预订单，自动关闭订单、归还Redis与数据库库存，最终保证Redis缓存和MySQL数据库的数据一致性。

## 项目模块说明
- controller：接口层，接收前端请求
- service：业务逻辑层
- mapper：数据库访问层
- common：公共包，包含DTO/VO、状态枚举、异常、工具类、过滤器，配置类，定时任务，rabbitmq...

## 启动说明
1. 准备MySQL，执行项目提供的SQL脚本，创建业务表
2. 启动Redis、RabbitMQ服务
3. 修改application.yml中的数据库、Redis、MQ连接配置
4. 启动SpringBoot项目，访问接口文档
